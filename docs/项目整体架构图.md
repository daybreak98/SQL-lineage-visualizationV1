## 三、核心请求流：`POST /api/sql/analyze`

```mermaid
sequenceDiagram
  autonumber
  participant U as 浏览器
  participant FE as Frontend<br/>api/client.ts
  participant C as analyze_controller
  participant P as sql_parse_service<br/>+ parse_recovery_pipeline
  participant QS as query_structure_service
  participant NR as name_resolver
  participant RS as derived_relation_<br/>schema_builder
  participant RU as cte_column_rollup_<br/>service ⭐
  participant GB as graph_builder<br/>+ merge_graphs
  participant SL as source_location_<br/>service
  participant EA as expression_analyzer
  participant M as models.py<br/>AnalysisResult

  U->>FE: 输入 SQL + dialect
  FE->>C: POST /api/sql/analyze<br/>{sql, dialect, analysis_options}
  C->>P: parse_sql(sql, dialect)
  P-->>C: ParseServiceResult<br/>(tree, diagnostics, output_fields)

  alt tree is None（解析失败）
    C->>P: ParseRecoveryPipeline.recover
    alt 恢复出 tree
      C->>QS: analyze_query_structure
      C->>NR: resolve_column_lineage_names
      C->>GB: build_*_graph + merge_graphs
    else 仅得到 expression_dependencies
      C->>P: PartialLineageEngine.build_from_sql
      C->>GB: build_table_structure_graph + build_column_lineage_graph
    end
    C-->>FE: status=partial / failed
  else tree 正常
    C->>QS: analyze_query_structure(tree)
    QS-->>C: cte_names / physical_table_names / has_cte / has_subquery
    C->>C: _load_metadata (从 SQLite)
    C->>RS: build_derived_relation_schemas
    C->>NR: resolve_column_lineage_names(tree, metadata, context)
    NR-->>C: lineages (immediate)

    alt has_cte or has_subquery
      C->>RU: CteColumnRollupService.rollup(immediate_deps)
      RU-->>C: root_dependencies（展开到物理根表）
      C->>C: lineage_result.lineages = root_lineages
    end

    C->>GB: build_table_structure_graph / build_cte_structure_graph
    C->>GB: build_column_lineage_graph(lineages)
    C->>GB: merge_graphs(...) → GraphModel
    GB-->>C: GraphViewModel(nodes, edges)

    opt include_expression_lineage
      C->>EA: analyze_select(tree)
      EA-->>C: metrics → expr_nodes/edges（并入图）
    end

    opt include_source_location
      C->>SL: build_source_locations(sql, target_entities)
      SL-->>C: source_locations
    end

    C->>M: _assemble_result(...)
    C-->>FE: AnalysisResult (schema 0.3.0-c09)
  end

  FE->>FE: analysisToGraph → graphPipeline → 节点/边/布局
  FE->>U: LineageCanvas 渲染（可拖拽 / 高亮 / 查询口径）
```

## 四、数据契约（前后端稳定接口）

| 端点 | 请求 | 响应 |
|---|---|---|
| `GET /api/health` | — | `{status, service, version}` |
| `POST /api/sql/analyze` | `AnalyzeRequest` | `AnalysisResult` (含 `graph_view_model`、`diagnostics_report`、`source_locations`、`semantics_report`、`summary`、`capabilities`) |
| `POST /api/sql/format` | `{sql, dialect}` | `FormatSqlResponse` |
| `POST /api/sql/convert` | `{sql, source_dialect, target_dialect, pretty}` | `ConvertSqlResponse` |
| `POST /api/metadata/import/preview` / `commit` | `MetadataImportRequest` | `MetadataImportResponse` |
| `GET /api/metadata/tables` | — | `MetadataTablesResponse` |
| `GET /api/metadata/columns?table_name=` | — | `MetadataColumnsResponse` |

**契约版本**：`schema_version = "0.3.0-c09"`，定义于 `backend/app/models.py`。

## 五、模块职责矩阵（高内聚低耦合）

| 层 | 目录 | 职责 | 依赖方向 |
|---|---|---|---|
| 表现层 | `frontend/src/components` `pages` | UI 渲染、交互、拖拽 | → workbench → api/client |
| 状态层 | `frontend/src/workbench` | Workbench 状态机：empty/ready/analyzing/analyzed/dirty/failed | → graphPipeline |
| 图渲染层 | `frontend/src/graphPipeline.ts` 等 | 后端 GraphViewModel → 节点/边/布局/投影 | → api/client |
| 接入层 | `frontend/src/api/client.ts` | fetch 封装、dialect 归一化 | → Backend API |
| 接口层 | `backend/app/api` | 路由、请求校验、组装响应 | → services / models |
| 应用层 | `backend/app/services` | 解析、结构、血缘、rollup、图构建、源码定位 | → domain / repositories |
| 领域层 | `backend/app/domain` | 领域模型：`LineagePath`、`ColumnRef`、`GraphModel` | （无外部依赖） |
| 持久层 | `backend/app/repositories` `db` | SQLite 元数据读写 + 迁移 | → SQLite |
| 契约层 | `backend/app/models.py` | Pydantic DTO，前后端稳定边界 | （被 api/services 共用） |

## 六、关键扩展点

- **解析容错**：`parse_recovery_pipeline` + `partial_lineage_engine` —— 即使 sqlglot 完全解析失败，仍可基于结构事实返回 `partial` 血缘。
- **CTE 根源展开**：`cte_column_rollup_service` —— 将 CTE/子查询的即时血缘沿 `DerivedRelationSchema` 递归展开到物理根表，并产出 `LineagePath` 与诊断。
- **图工程化**：`graph_builder` + `graph_layout_planner` + `graph_crossing_minimizer` + `graph_port_order_optimizer` + `graph_semantic_layering` —— 后端已做布局/交叉最小化/端口排序，前端 `graphPipeline` + `graphComfortLayout` 再做舒适化渲染。
- **方言转换**：`format_controller` 支持 spark/hive/starrocks，含风险函数检测（`RISKY_FUNCTIONS_BY_TARGET`）与源大小写保留（`CASE_PRESERVED_WORDS`）。
- **元数据闭环**：`MetadataDialog` → `metadata_import_service` (preview/commit) → SQLite → `metadata_repository` → `analyze` 时通过 `_load_metadata` 回灌列信息。
