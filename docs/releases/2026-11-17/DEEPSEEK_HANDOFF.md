# DeepSeek 接手提示词（可整页复制）

请接手一个 SQL／JSON 亚字段血缘工作台，先定位问题并给出可复核的短交付。入口：[GitHub master](https://github.com/daybreak98/SQL-lineage-visualizationV1/tree/master)。以你实际检出的 master 和随交付提供的 [交付说明](./DELIVERY.md)、[评估记录](./EVALUATION.md)、[决策卡](./DECISION_CARD.md) 为准，记录实际读到的版本，不猜发布状态。按交付说明启动本地服务，从原工作台「亚字段血缘」进入 `/?view=subfield`，只用公开合成示例。已有定向证据包括页面路径聚焦、重跑清理、窄屏适配，本地证据包下载与切根失效，以及冲突源列声明被 API 拒绝。证据仅覆盖已测页面和本地静态 API。

**先做一件事。** 优先核查同脚本 CTE 的唯一生产槽与来源绑定。用一组自写合成正反例：正例从两层显式投影追到唯一源列和字面路径；负例加入同名竞争源后保持未决，同时保留另一条已证路径和独立整串观察。只报告有证据的槽位与原文位置。能复现再交最小修复建议；没有复现就报告范围和缺证。然后才处理动态路径的可定位调用事件（不猜运行期键），以及不透明 UDF 的 SQL 层整列实参（内部语义要有函数身份、注册版本和实现或可核契约）。一次只推进一个缺口。

**边界与分工。** 只读诊断摘要仍待用户决定，尚未实施；不要自行实装。真实跨任务链等生效视图、实际中间表 DDL、同一业务小时成功写入与实际扫描的同一不可变版本凭证，到件并核验后才逐边分析。缺证时保持未决，不能从字段图、同名分区、共现、空消费列表或高置信分推导可删。你负责复现、证据和建议；静态规则由算法维护者修改，API 与数据接入由后端维护者修改，界面由前端维护者修改；独立评估者核对结果，负责人验收。当前接手指令不授权改代码、发布、生产执行或调整模型配置。

**只使用显式提供的数据。** 本地原件只有在接手环境明确提供后才可访问。到件先核权限和来源、归档及成员清单、原始字节哈希、顺序、方言与版本，再由独立评估者确认冻结输入和真值。缺件直接登记，不寻找或重建私有材料。不要执行原件里的 Shell 或 SQL，不解封套来更改首跑分类，不修改冻结输入、响应、阈值、分母或金标，不用留出件调规则和写样本特判。不要把原文、内部标识、成员名、逐项结果或本地路径写进公开仓库、日志或交接答复。

**短验收。** 回报实际版本、最小合成输入与验证命令、预期和实际、证据位置、未决及改动归属。分别注明：① 静态解析和同批响应一致性；② 局部计分单位（动态事件、整列实参、同脚本传播分别报告，空预测时精确率 N/A）；③ 赛题全量 O1/O2 无独立真值则写「未计分」。不把解析、匹配或局部值传递推成实际引擎执行、跨批次状态、行集等价或删键安全。到达最小验收就停；没有授权，不另跑全量。
