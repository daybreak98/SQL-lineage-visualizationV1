# 2026-11-19｜亚字段血缘团队简报

本次交付聚焦 J「亚字段血缘解析」的试用流程：粘贴 SQL 后先读核查结论，再查某个 JSON 键、切换输出范围，并回到读取该键的原 SQL。页面沿用原工作台的组件和分隔条。文中示例使用合成数据。

## 今日交付

- **SQL 定位**：后端能确认原文区间时，编辑器优先选中带引号的路径字面量，如 `'$.media_id'`；旧响应只有调用位置时，仍能定位函数。
- **状态区分**：「SQL 分析待确认项」描述整次分析；「暂不能判断」描述所选键。两者独立，例如分析待确认项为 0 时，若一个输出透传整列，某个键仍可能无法判定。
- **输出范围**：默认显示全部可选输出的实际数量；更改范围后旧回执失效；零选时不提交查键，可一键恢复全部。

## 外审与边界

本机 DeepSeek Harness 对较早的冻结候选做了一次隔离静态审查：用独立会话和只读配置，仅提交公开差异与相关源文件片段，记录确认模型未调用工具。它提示了更改检查输入后旧状态文案可能残留，以及查键下载容易被误读为剪枝评审。后续修复单独验收；这次外审不等于浏览器验收。

本次未上线两跳接入或构图缓存，也未对已有真实 ETL 语料重算准确率和召回率。界面结论仅限本次 SQL 和所选输出，未验证执行行集或修改影响，不能据此决定生产删键。下一步先独立验收查键回执，再试用两步读取证据，之后用既有真实难例复测指标。
