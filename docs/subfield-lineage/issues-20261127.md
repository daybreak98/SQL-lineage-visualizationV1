## 1. 分层地图

| 层 | 职责 | 回答什么 | 本台账的问题 |
|---|---|---|---|
| 解析层 | SQL 文本 → AST | 能不能变成树 | A-06、A-07 |
| 分析层 | AST → 使用点 / 输出列 / 端点证据 | 哪个键被读了、落到哪列 | A-01、A-04、A-08、A-09 |
| 判定层 | 使用点 + 候选键 → 结论 | **这个键能不能剪** | A-02、A-03、A-05 |
| 产品层 | 把结论表达给人 | 用户会不会误读 | A-10 |

**关键：召回失败在分析层，可剪枝失败在判定层，两者互不拯救。**

## 2. 问题明细

### A-01 `select *` 派生表不展开（P0，召回的真凶）

**现象**

```sql
from (select * , get_json_object(common_stid,'$.stid_container') as stid_container
      from src) t1
select generic_clean('browse_type', get_json_object(style_type,'$.browseType'))
```

外层 `style_type` 来自 `(select * …) t1`，因为不展开 `*`，列绑不上 → 整个调用记 `UNKNOWN_JSON_INPUT` → **连"这条键被读过"的 `uses` 都不产生**。

**实测（2×2 隔离，只改两个变量）**

| 子查询 | UDF 包裹 | 根 kind | 识别到的 EXTRACT |
|---|---|---|---|
| 显式列 | 否 | `EXTRACT` | 1 ✅ |
| 显式列 | 是 | `UNKNOWN` | **1**（use 在，结论没了） |
| `select *` | 否 | `UNKNOWN` | **0**（use 消失） |
| `select *` | 是 | `UNKNOWN` | **0** |

**结论**：`select *` 单独就足以让键消失；UDF 只会让结论消失。

**影响**：单例实测召回 **50%（2/4）**，两条漏检全部由此产生；该 SQL `UNBOUND_COLUMN` 110 条。

**修法**：把 `star_expansion_service`（主血缘入口已在用）接进亚字段路径；或按 `source_schemas` 展开。

**验收**：`select *` 形态的召回与显式列形态**差值 ≤ 0**。

### A-02 判定层"一票否决"（P0）

**证据**

```python
# subfield_review.py:140
if result["unknowns"] or coverage.get("parsed") is not True or coverage.get("partial"):
    return unknown("ANALYSIS_INCOMPLETE")     # 候选键一个都不看
```

同一条 `self.unknowns` 在 `mark_direct_extracts`（`subfield.py:1595`）与 `_closed_direct_demands`（`subfield_review.py:77`）各出现一次。

**实测**：单例 SQL 有 208 条未决，其中 110 条是 `UNBOUND_COLUMN`、70 条 `UNKNOWN_FUNCTION`，大多与提问的键无关。结果：**4 条候选键全部 `UNKNOWN`，包括那 2 条明明已经读到的**。

**影响**：判定层产出恒为 0；即使召回做到 100%，结论仍是 0。

**修法**：未决收敛到 carrier / scope / 键级（`blocking_scope` 三档：`BLOCK_ALL` / `BLOCK_SCOPE` / `BLOCK_KEY`）。

**验收**：一条与提问键无关的未决，不得使该键的判定变为 `UNKNOWN`。

### A-03 判定要求"整条语句只剩取键"（P0）

**证据**

```python
# subfield_review.py:77  _closed_direct_demands
if (... or len(result["uses"]) != len(mappings)):
    return {}                                  # 每一列都必须有消费点
...
if (use["kind"], use["role"], use["clause"]) != ("EXTRACT", "VALUE", "SELECT"):
    return {}
```

**实测**：一个 19 列的真实 DWD 形状（15 列透传 + 4 列取键 + 一个 `WHERE` 常量，**零未决**）：

```
analysis_status = JSON_USE_OBSERVED     ✅ 状态对
candidate       = UNKNOWN / PROTECTED_PATH_UNVERIFIED   ❌
```

即：树对、状态对、端点也够，仍判不出，因为入口只接受"全投影都是取键"的玩具形状。

**修法**：取消 `uses == mappings` 的形状前提，改为按 carrier 逐条闭合。

**验收**：混合投影的表上，被保护区间的键能出结论。

### A-04 「基表 + 取键」没有端点证据（P0）

**实测（三种形态）**

| 形态 | `port_reads` | `terminal_binding` | `direct_extract_read` |
|---|---|---|---|
| CTE + 取键 | 1 | 无 | 无 |
| 基表 + 整列 | 0 | `SQL_NAMED_RELATION_COLUMN` | 无 |
| **基表 + 取键** | **0** | **无** | 仅当全投影取键且零未决 |

代码依据：`bound_cte_read` 要求 `producer.is_cte`（`subfield.py:1573`）；`terminal_column_binding` 要求 `value.kind == "WHOLE_RAW"`（`:1681`）。

**影响**：生产 ETL 从基表直接取键是常态，这一格空着 = 结构性判不了。

**修法**：新增「源列端点」一类证据（表 + 列 + 路径 + 原文坐标）。

**验收**：`SELECT get_json_object(t.p,'$.k') FROM lab.t t` 与等价 CTE 写法结论一致。

### A-07 Jinja `{% %}` 导致白卷（P1）

**证据**

```python
# complex_sql_guard/preflight.py:19
re.compile(r"\$\{[^}]+\}|#\{[^}]+\}|<#.*?>|</#.*?>")   # 无 {% %}
```

**实测**：15 份生产文件中 2 份 `status=partial / tree=None`；对同一文件只删 `{% … %}` 即 `success`，只换 `{{ … }}` 仍 `partial`。

**影响**：`tree=None` 时主血缘入口也拿不到列级结果，只能正则回退出表级。

### A-08 UDF 值不可知（P1）

**实测**：单文件 70 条 `UNKNOWN_FUNCTION`，分布：`GENERIC_CLEAN` 38、`TO_JSON_EXCLUDE_EMPTY` 5、`BIGINT` 3、编解码 7、业务变换 5、其余 12。

**关键**：把 UDF 全当透传，未决 129 → 122（**−7**），端点证据仍 0。原因是"全或无"：表达式里任意一层 UDF 未知，整列就 UNKNOWN。

**建议语义契约**：每个入参四态（N/T/V/U）+ 输出归属（`SINGLE_V` / `MULTI_V` / `NONE` / `U`）+ 版本哈希；默认 `OPAQUE`；**UDF 语义词表必须走独立请求字段，不能复用 `source_schemas`**（实测：一传声明，`direct_extract_read` 从 2 变 0）。

### A-09 concat 路径回退（P2，dev 新增）

**实测**

| 版本 | `get_json_object(t.p, concat('$.','k'))` |
|---|---|
| master | `EXTRACT ('p','$.k')`，未决 0 |
| dev | `UNKNOWN`，`CONCAT_FUNCTION_BINDING_UNVERIFIED` |

**性质**：有意保守（Spark 可能把未限定 `CONCAT` 解析为会话函数）。技术上站得住，但属于**能力回退**，需要统计真实语料里的出现频次来决定是否接受。

---

### A-10 无"判定范围"表达（P1）

**现象**：判定为 `UNKNOWN` 与"没用到"在界面上都表现为"没有结论"。剪枝场景里前者必须保留、后者支持删除，后果相反。

**要求**：任何档位下 UI 必须显示「该键未判 / 判定范围」，并且 **`N` 不得由 `U` 推导**。

## 4. 修复优先级与依赖

```
A-01 (select * 展开)  ──┐
                        ├─→ 提高召回
A-07 (Jinja 正则)     ──┘

A-02 (未决局部化)  ──┐
                     ├─→ 让结论从 0 变正
A-03 (取消形状假设) ──┤
A-04 (源列端点)     ──┘

A-06 (接解析层)  只降低未决数量，不改变结论是否为 0
A-08 (UDF 语义表) 只减少 UNKNOWN_FUNCTION，不改变结论是否为 0
```

**若只做 A-06 + A-08**：账面未决从 129 降到 100 量级，**可剪枝结论仍是 0**。
